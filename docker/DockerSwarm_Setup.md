# Настройка кластера Docker Swarm

Эта инструкция описывает, как настроить кластер Docker Swarm с поддержкой IPv6 и упрощённой IPv4 адресации согласно изложенной логики.

## Шаг 1. Установка Docker

На всех узлах (и мастерах, и воркерах) выполните:
```bash
sudo apt update
sudo apt install docker.io
sudo systemctl enable docker
sudo systemctl start docker
```

## Шаг 2. Инициализация Swarm

Выберите мастер-узел (например, узел `aa` с IPv4-адресом **10.11** и IPv6-адресом **fdaa::**). На этом узле выполните:
```bash
docker swarm init --advertise-addr fdaa::
```
При необходимости можно указать упрощённый IPv4-адрес:
```bash
docker swarm init --advertise-addr 10.11
```

## Шаг 3. Присоединение воркеров

На воркер-узлах (например, узел `ab` с IPv4-адресом **10.12** и IPv6-адресом **fdab::**) выполните команду, выведенную при инициализации, например:
```bash
docker swarm join --token <TOKEN> fdaa::2377
```
или, используя IPv4:
```bash
docker swarm join --token <TOKEN> 10.11:2377
```

## Шаг 4. Создание оверлейной сети

Создайте сеть с поддержкой IPv6 (и при необходимости IPv4) для работы контейнеров:
```bash
docker network create \
  --driver overlay \
  --subnet fdaa::/64 \
  --ipv6 \
  swarm_net
```
*Примечание:* При внешней маршрутизации используйте упрощённые IPv4 адреса (например, 10.11 для мастера, 10.12 для воркеров).

## Шаг 5. Запуск сервисов

Запустите сервисы, подключённые к созданной сети:
```bash
docker service create --name my_service \
  --network swarm_net \
  nginx
```

## Шаг 6. Проверка связи

- **IPv6:** Проверьте связь между контейнерами:
  ```bash
  docker exec -it <CONTAINER_ID> ping6 fdaa::1
  ```
  И убедитесь, что контейнеры могут выходить в интернет:
  ```bash
  docker exec -it <CONTAINER_ID> curl -6 http://google.com
  ```
- **IPv4:** Проверьте упрощённую адресацию:
  ```bash
  docker exec -it <CONTAINER_ID> ping -c 1 10.11
  ```

---

В этом документе использована логика упрощённой адресации: мастер-узлы получают адреса вида **10.11**, **10.22** и т.д., а воркеры – адреса вроде **10.12**, **10.13** и т.д. При этом для маршрутизации и управления кластером используются как IPv6-адреса (обеспечивающие масштабируемость), так и упрощённые IPv4-адреса для удобства.
