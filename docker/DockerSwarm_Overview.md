# Обзор Docker Swarm и параллельных кластеров

Данный документ содержит общую информацию о кластерах Docker Swarm, используемых для управления контейнеризированными сервисами, а также о логике распределения адресов и параллельной работе двух окружений.

## Параллельные кластеры

Для разделения тестовой и продакшн-сред используются два параллельных кластера:

- **Пользователь c (Continuous Integration, тестовая среда)**  
  Узлы этого кластера используют подсеть **fcaa::** для IPv6. При этом для IPv4 применяется упрощённая схема, например, мастер-узел получает адрес **10.11**, воркеры – **10.12**, **10.13** и т.д.

- **Пользователь d (Continuous Deployment, продакшн)**  
  Узлы данного кластера используют подсеть **fdaa::** для IPv6, а для IPv4 адресация аналогична: мастер – **10.11** (либо иные повторяющиеся адреса вроде 10.22, 10.33 и т.д.), воркеры – **10.12**, **10.13** и т.д.

Эта схема обеспечивает четкое разделение окружений, что способствует безопасному развертыванию и удобному управлению кластером.

## Логика распределения адресов

- **IPv6 адресация:**  
  Каждый узел получает собственную подсеть `/64`:
  - Например, узел `aa` может иметь адресацию `fdaa::/64` или `fcaa::/64` в зависимости от среды.
  - Контейнеры на узле наследуют адреса в пределах выделенной подсети (например, `fdaa::1`, `fdaa::2`).

- **IPv4 адресация:**  
  Применяется упрощённая схема:
  - Мастер-узлам назначаются адреса с повторяющимися цифрами:  
    - `10.11` для узла **aa**,  
    - `10.22` для узла **bb** и т.д.
  - Воркерам назначаются адреса по логике групп, например:  
    - `10.12` для узла **ab**,  
    - `10.13` для узла **ac** и т.д.

## Преимущества такой архитектуры

- **Разделение окружений:**  
  Одновременная работа двух кластеров под разными пользователями обеспечивает безопасное тестирование и развертывание.

- **Удобство управления:**  
  Единая схема именования и упрощённая адресация облегчают администрирование и минимизируют риск ошибок при ручном вводе.

- **Масштабируемость и интеграция:**  
  Использование IPv6 с выделенными подсетями для каждого узла упрощает маршрутизацию, а упрощённые IPv4-адреса позволяют быстро ориентироваться в инфраструктуре.
