# Обзор Docker Swarm и параллельных кластеров

В этой документации описывается архитектура и логика работы параллельных кластеров Docker Swarm, управляемых пользователями **c** (тестовая среда, CI) и **d** (продакшн, CD).

## Архитектура и общая сеть

- **Общая IPv6 подсеть:**  
  Все узлы кластеров объединены в рамках общей IPv6 подсети с 16-битной маской (например, `fd00::/16`). Это позволяет логически объединить параллельные кластеры в единое пространство.

- **Выделенные подсети для узлов:**  
  Каждый узел получает уникальную подсеть `/64` внутри общей сети:
  - Для продакшн-среды (пользователь **d**) мастер-узел может использовать, например, `fdaa::/64`, а воркеры – `fdab::/64`, `fdac::/64` и т.д.
  - Для тестовой среды (пользователь **c**) мастер-узел использует, например, `fcaa::/64`, а воркеры – `fcab::/64`, `fcac::/64` и т.д.

## IPv4 адресация

Используется упрощённая схема для удобства:
- **Мастер-узлы:**  
  Адреса вида:
  - `10.11` для узла **aa**
  - `10.22` для узла **bb**
  - и т.д.
- **Воркер-узлы:**  
  Адреса распределяются по группам, например:
  - `10.12` для узла **ab**
  - `10.13` для узла **ac**
  - и т.д.

## Параллельные кластеры

- **Кластер CI (пользователь c):**  
  Узлы используют выделенные подсети с префиксом `fcaa::/64` (для мастера) и соответствующие для воркеров.

- **Кластер CD (пользователь d):**  
  Узлы используют выделенные подсети с префиксом `fdaa::/64` (для мастера) и соответствующие для воркеров.
