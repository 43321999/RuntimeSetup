1.  **Локальная генерация конфигов:**
    *   **Генерация ключей:** Локальная генерация возможна, но безопаснее и удобнее генерировать ключи непосредственно на целевых машинах (сервере и клиентах) с помощью Ansible. Это избавляет от необходимости передавать приватные ключи по сети или хранить их централизованно.
    *   **Определение хостов:** Да, список хостов берем из `vars.yml` или, что лучше, из инвентарного файла Ansible.
    *   **IP-адрес сервера:** Это действительно ключевой момент. Получить публичный IP сервера можно несколькими способами прямо во время выполнения плейбука:
        *   **Ansible Facts:** Если Ansible подключается к серверу по его публичному IP, то факт `ansible_default_ipv4.address` будет содержать нужный адрес.
        *   **Внешний запрос:** Можно выполнить на сервере команду типа `curl ifconfig.me` или `dig +short myip.opendns.com @resolver1.opendns.com` с помощью модуля `command` или `shell` и зарегистрировать результат.
        *   **Инвентарный файл:** Можно явно указать публичный IP сервера в инвентарном файле Ansible.
    *   **Создание конфигов:** Вместо создания полных файлов локально, гораздо гибче использовать шаблонизатор Jinja2 и модуль `template` в Ansible. Создаются шаблоны (`.j2`) для конфигурации сервера и клиента, а Ansible заполняет их нужными данными (ключами, IP-адресами) прямо на целевых хостах.

2.  **Установка и настройка:**

    *   **Перенос конфигов:** Как упомянуто выше, лучше не переносить готовые конфиги, а генерировать их на месте из шаблонов.

3.  **Запуск и автозагрузка:**

**Предлагаемый сценарий (улучшенный):**

*   **Подготовка:**
    *   Определить группы `[wireguard_servers]` и `[wireguard_clients]` в инвентарном файле Ansible.
    *   Определить переменные для сети WireGuard (приватные подсети, порт сервера) в файлах переменных (`group_vars/all`, `group_vars/wireguard_servers` и т.д.).

*   **Роль 1: `wireguard-common` (Общая настройка)**
    *   **Цель:** Все хосты (`wireguard_servers`, `wireguard_clients`).
    *   Установить пакеты `wireguard`, `wireguard-tools`.
    *   *На каждом хосте*: Сгенерировать пару ключей (приватный/публичный) с помощью `wg genkey | tee privatekey | wg pubkey > publickey`. Сохранить ключи в `/etc/wireguard/` с правильными правами.
    *   Собрать публичные ключи со всех хостов (используя модуль `slurp` или `fetch`, или просто зарегистрировав вывод команды `wg pubkey` как факт).

*   **Роль 2: `wireguard-server` (Настройка сервера)**
    *   **Цель:** `wireguard_servers`.
    *   Получить публичный IP сервера (используя факты Ansible или внешний запрос).
    *   Получить публичные ключи всех клиентов (из фактов, собранных на предыдущем шаге).
    *   Распределить приватные IP-адреса для сервера и каждого клиента из выделенной подсети.
    *   Сгенерировать конфигурационный файл сервера (`/etc/wireguard/wg0.conf`) с помощью модуля `template` и Jinja2-шаблона. Шаблон будет включать:
        *   Приватный ключ сервера.
        *   Приватный IP-адрес сервера.
        *   Порт для прослушивания.
        *   Секции `[Peer]` для каждого клиента с их публичными ключами и выделенными приватными IP.
    *   Включить и запустить службу `wg-quick@wg0.service`.

*   **Роль 3: `wireguard-client` (Настройка клиентов)**
    *   **Цель:** `wireguard_clients`.
    *   Получить публичный ключ сервера, его публичный IP-адрес и порт (из фактов сервера).
    *   Получить выделенный приватный IP-адрес для данного клиента.
    *   Сгенерировать конфигурационный файл клиента (`/etc/wireguard/wg0.conf`) с помощью `template`. Шаблон будет включать:
        *   Приватный ключ клиента.
        *   Приватный IP-адрес клиента.
        *   Секцию `[Peer]` для сервера с его публичным ключом, публичным IP:портом и `AllowedIPs` (обычно это приватная подсеть WireGuard).
    *   Включить и запустить службу `wg-quick@wg0.service`.

*   **Основной плейбук (`setup.yml`):**
    *   Импортирует или включает плейбуки/роли (`wireguard-common`, `wireguard-server`, `wireguard-client`) в правильном порядке.
    *   Управляет общим процессом.

### 💡 Подход:

1. Один playbook — **обрабатывает и серверы, и клиентов**.
2. У каждого хоста — свои переменные (`host_vars/`).
3. Шаблон адаптируется — **если это сервер, добавляем клиентов как peers**.
4. На клиентах — один peer (сервер).

### 📄 `playbook.yml`

```yaml
- name: Настройка WireGuard на всех узлах
  hosts: wireguard
  become: true

  tasks:
    - name: Генерация WireGuard-конфига
      template:
        src: wg0.conf.j2
        dest: /etc/wireguard/wg0.conf
        owner: root
        group: root
        mode: '0600'
```

---

### 📄 `templates/wg0.conf.j2`

```jinja2
[Interface]
Address = {{ interface_address }}
PrivateKey = {{ private_key }}
ListenPort = {{ listen_port | default(omit) }}

{% for peer in peers %}
[Peer]
PublicKey = {{ peer.public_key }}
AllowedIPs = {{ peer.allowed_ips }}
{% if peer.endpoint is defined %}
Endpoint = {{ peer.endpoint }}
{% endif %}
{% if peer.persistent_keepalive is defined %}
PersistentKeepalive = {{ peer.persistent_keepalive }}
{% endif %}
{% endfor %}
```
