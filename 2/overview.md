# Рекомендации по разделению документации

Для повышения удобства поддержки и масштабируемости всей инфраструктуры рекомендуется:

1. **Разделение уровней абстракции:**  
   - **Overview:** Общий взгляд на архитектуру сети, кластеров, адресное пространство (например, общая сеть /7, узлы /16).  
   - **Setup:** Пошаговая инструкция по настройке конкретного узла или сервиса.

2. **Вынос специфичных настроек:**  
   - **IPv4‑упрощённая адресация:** Оформить в отдельном файле, так как она относится к локальной сети и не является ключевой для CI/CD кластеризации.  
   - **WireGuard и RoadWarrior:** Настройки, связанные с этими сервисами, лучше вынести в отдельные файлы (например, `wireguard_overview.md`, `wireguard_setup.md` и `roadwarrior.md`), чтобы при необходимости можно было их применять только там, где требуется.
   - **Интравеб‑адресация и локальные сети провайдера:** Адреса типа `00::164`, `01::164`, …, а также локальные IPv4‑подсети (например, 10.0/24, 10.115.1/17) описать либо в отдельном файле для каждого сайта, либо включить в обзор уровня отдельного сайта.

3. **Единообразие:**  
   - Документация должна быть структурирована так, чтобы всегда было понятно, где найти общий обзор (overview) и где – детальную настройку (setup) для конкретного узла или сервиса.

Данная структура позволит впоследствии легко расширять документацию, добавлять новые подсистемы и поддерживать актуальность инструкций для всех узлов и сервисов.
